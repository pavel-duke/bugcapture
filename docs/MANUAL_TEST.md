# Ручная проверка релиза

Этот чек-лист проходится на ZIP из `release`, а не на dev-сервере Vite.

## Подготовка

```bash
npm ci
npm run verify
npm run demo
```

Проверить `release/BugCapture-v0.4.0-chromium.zip.sha256`, распаковать `release/BugCapture-v0.4.0-chromium.zip` во временную постоянную папку. Открыть `http://127.0.0.1:4177`.

## Полный сценарий

Для каждого браузера:

- [ ] установить распакованный release build;
- [ ] проверить название и версию 0.4.0;
- [ ] закрепить BugCapture;
- [ ] открыть demo page;
- [ ] открыть popup и проверить правильное название браузера;
- [ ] нажать «Начать запись»;
- [ ] убедиться, что видны `● Запись`, таймер и системная плашка debugger;
- [ ] нажать GET 200;
- [ ] нажать GET 404;
- [ ] нажать POST 500 + token;
- [ ] нажать console.error;
- [ ] нажать «Отметить момент»;
- [ ] нажать «Остановить»;
- [ ] открыть Network Explorer до экспорта;
- [ ] проверить поиск по URL, method, status и host;
- [ ] проверить All, Errors, 2xx, 3xx, 4xx, 5xx и Failed;
- [ ] включить «Показать только проблемные»;
- [ ] открыть 500 и failed request, проверить безопасные headers и initiator;
- [ ] убедиться, что request/response body нигде не показаны;
- [ ] вернуться и нажать «Экспортировать файлы»;
- [ ] убедиться, что скачались WEBM, TXT и safe HAR;
- [ ] открыть WEBM и проверить изображение вкладки;
- [ ] открыть TXT и проверить Network 404/500 и Console error;
- [ ] открыть safe HAR JSON/HAR viewer;
- [ ] найти строку `BUGCAPTURE_TEST_SECRET_123456789` во всех output-файлах — совпадений должно быть 0;
- [ ] проверить `authorization: [REDACTED]`;
- [ ] проверить `cookie: [REDACTED]` или отсутствие Cookie;
- [ ] проверить `token=[REDACTED]`;
- [ ] проверить TVM/Service Ticket и signed URL — исходных значений быть не должно;
- [ ] повторно скачать весь пакет одной кнопкой.
